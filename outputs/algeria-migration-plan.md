# 阿尔及利亚项目迁移计划

## 1. 迁移目标

本次迁移目标是将阿尔及利亚项目从现有环境平滑迁移到新的高可用环境，完成数据库和 MinIO 数据迁移、应用服务高可用部署、DNS 入口切换，并保留可回滚能力。

核心目标：

- 保证数据库和 MinIO 数据完整可恢复。
- 新环境具备高可用能力，避免单点故障。
- DNS 切换窗口可控，业务中断时间尽量压缩。
- 旧环境在观察期内保留，必要时可快速回滚。

## 2. 时间计划

以正式割接日 `D 日` 为基准，建议选择业务低峰期执行，预留 `4-6 小时` 正式割接窗口。

| 阶段 | 时间 | 工作内容 | 产出 |
| --- | --- | --- | --- |
| 准备阶段 | D-7 ~ D-5 | 确认旧环境架构、数据量、服务器规格、域名、证书、网络策略、账号权限、回滚方式 | 迁移确认清单 |
| 新环境准备 | D-4 ~ D-2 | 初始化服务器、配置网络、防火墙、时间同步、磁盘挂载、系统参数 | 新环境基础资源可用 |
| 预演备份与恢复 | D-2 ~ D-1 | 对数据库和 MinIO 执行一次备份恢复演练，确认恢复耗时和校验方式 | 恢复演练结果 |
| 变更冻结 | D-1 | 暂停非必要发布和配置变更，提前降低 DNS TTL，例如调整为 300 秒 | 冻结确认 |
| 正式迁移 | D 日 | 停写、最终备份、部署/验证新 HA、恢复数据库和 MinIO、业务验证、DNS 切换 | 新环境正式接管 |
| 观察期 | D+1 ~ D+3 | 监控新环境，旧环境保留只读或待命状态，确认无问题后进入下线流程 | 迁移验收记录 |

## 3. 服务器资源规划

以下为建议资源，最终规格需结合当前数据量、并发量、对象存储容量和未来增长空间确认。

| 角色 | 数量 | 建议配置 | 主要用途 |
| --- | ---: | --- | --- |
| 负载均衡 / VIP 节点 | 2 台 | 2C / 4G / 50G | Nginx/HAProxy/Keepalived，提供统一入口和健康检查 |
| 应用节点 | 2-3 台 | 4C / 8G / 100G+ | 部署业务服务，多实例运行 |
| 数据库 HA 节点 | 3 台 | 8C / 16G / SSD 数据盘 | MySQL InnoDB Cluster 或等价数据库 HA |
| MinIO 节点 | 4 台起 | 4C / 8G / 独立数据盘 | 分布式 MinIO 对象存储 |
| 备份存储 | 1 套 | 容量不低于当前数据量 2 倍 | 保存数据库备份、MinIO 备份、校验文件和迁移日志 |

基础要求：

- 所有服务器时间必须通过 NTP 同步。
- 数据库和 MinIO 节点建议使用 SSD 或性能稳定的数据盘。
- MinIO 分布式节点建议磁盘规格一致，避免容量和性能不均衡。
- 新旧环境之间需要保证数据库备份、MinIO 对象同步和应用访问所需网络连通。
- 公网只开放业务入口端口，数据库、MinIO 内部端口仅允许可信网段访问。

## 4. 数据库备份计划

### 4.1 迁移前备份

在正式迁移前执行一次数据库全量备份，并完成恢复演练。

建议步骤：

1. 确认数据库版本、字符集、时区、库表数量、数据量和账号权限。
2. 执行全量备份。
3. 记录 binlog/GTID 位点，用于增量追平。
4. 对备份文件生成 SHA256 或等价校验值。
5. 将备份文件复制到备份存储和新环境。
6. 在新环境执行恢复演练，确认恢复耗时和数据完整性。

### 4.2 正式割接备份

正式迁移时需要进入停写窗口，确保最终数据一致。

建议步骤：

1. 通知业务进入维护或只读状态。
2. 停止应用写入流量。
3. 执行最终全量备份，或基于预备份执行最终增量备份。
4. 再次记录备份时间、binlog/GTID 位点和校验值。
5. 将最终备份传输到新环境。

### 4.3 数据库校验

数据库恢复后至少完成以下校验：

- 核心库表数量一致。
- 关键业务表记录数一致。
- 数据库用户、权限、字符集和时区符合要求。
- 应用连接新数据库成功。
- 登录、查询、写入、核心业务流程验证通过。

## 5. MinIO 备份计划

### 5.1 迁移前同步

MinIO 数据量通常较大，建议提前做预同步，正式割接时只同步增量。

建议步骤：

1. 统计 bucket 列表、对象数量、总容量、用户、策略、access key、生命周期和复制策略。
2. 使用 `mc mirror` 或等价方式将对象数据同步到新环境或备份存储。
3. 导出并记录 bucket policy、用户策略、访问权限等元数据。
4. 抽样校验对象大小、ETag/hash 和业务读取结果。
5. 记录预同步耗时和剩余增量规模。

### 5.2 正式割接同步

正式迁移时需要停止对象写入后再执行最终同步。

建议步骤：

1. 停止应用对旧 MinIO 的写入。
2. 执行最终增量同步。
3. 同步 bucket policy、用户、访问策略和必要的访问密钥配置。
4. 校验核心 bucket、关键对象和业务文件访问。
5. 将应用配置切换到新 MinIO。

### 5.3 MinIO 校验

MinIO 恢复后至少完成以下校验：

- bucket 数量和名称一致。
- 核心 bucket 对象数量和容量符合预期。
- 关键业务文件可下载、预览或被应用正常引用。
- 应用上传新文件成功。
- 用户、策略和访问权限符合要求。

## 6. 新 HA 环境部署

### 6.1 基础环境部署

1. 初始化操作系统和基础安全配置。
2. 配置主机名、内网 IP、DNS、NTP 和防火墙。
3. 挂载数据盘并设置开机自动挂载。
4. 安装 Docker 或项目所需运行时。
5. 配置系统日志、磁盘监控和基础告警。

### 6.2 数据库 HA 部署

1. 在 3 台数据库节点部署数据库服务。
2. 配置数据库 HA，例如 MySQL InnoDB Cluster。
3. 确认主节点、从节点、复制状态和故障转移能力。
4. 创建业务所需数据库、用户和权限。
5. 恢复迁移数据并执行一致性校验。

### 6.3 MinIO HA 部署

1. 在至少 4 台节点部署分布式 MinIO。
2. 配置独立数据盘和统一服务参数。
3. 配置 MinIO 控制台和内部访问地址。
4. 创建 bucket、用户、策略和访问权限。
5. 恢复对象数据并执行读写校验。

### 6.4 应用 HA 部署

1. 在应用节点部署业务服务多实例。
2. 应用连接新数据库和新 MinIO。
3. 配置服务健康检查。
4. 配置负载均衡后端节点。
5. 验证应用启动、日志、接口、登录和核心业务流程。

## 7. 数据库和 MinIO 还原流程

正式还原顺序建议如下：

1. 确认新数据库 HA 集群状态正常。
2. 将最终数据库备份恢复到新数据库。
3. 校验数据库完整性和核心业务数据。
4. 确认新 MinIO 分布式集群状态正常。
5. 将最终 MinIO 对象数据和元数据恢复到新 MinIO。
6. 校验对象数量、关键文件和访问权限。
7. 修改应用配置，使应用连接新数据库和新 MinIO。
8. 启动应用服务并执行完整业务验证。

## 8. DNS 切换计划

### 8.1 切换前准备

1. D-1 提前将业务域名 TTL 调整为 300 秒或客户 DNS 平台允许的较低值。
2. 确认新 HA 入口公网 IP、证书和负载均衡配置。
3. 确认新环境健康检查通过。
4. 准备 DNS 回滚记录，保留旧环境 IP。

### 8.2 正式切换

1. 业务进入维护或只读状态。
2. 完成数据库和 MinIO 最终同步。
3. 在新环境完成业务验证。
4. 将域名 A 记录或 CNAME 指向新 HA 入口。
5. 等待 DNS 生效并进行多地区解析验证。
6. 验证公网访问、登录、核心 API、文件上传下载。

### 8.3 切换后观察

切换后建议持续观察至少 24-72 小时：

- 应用错误率。
- 接口延迟。
- 数据库连接数、复制状态和慢查询。
- MinIO 节点状态、磁盘使用率和对象读写。
- 负载均衡健康检查。
- 服务器 CPU、内存、磁盘和网络流量。

## 9. 回滚方案

如果正式切换后出现严重问题，可执行回滚。

建议回滚触发条件：

- 数据库恢复失败或核心数据不一致。
- MinIO 对象缺失、权限异常或业务文件无法读取。
- 新 HA 健康检查持续失败。
- DNS 切换后核心业务不可用。
- 错误率、延迟或资源使用超过预设阈值。

回滚步骤：

1. 停止新环境业务写入。
2. 将 DNS 切回旧环境入口。
3. 恢复旧环境应用写入。
4. 如新环境已产生新数据，评估是否需要反向同步或人工处理。
5. 保留新环境日志、数据库状态和 MinIO 状态，用于问题分析。

注意：回滚前必须确认新环境是否已经产生业务写入，避免新旧环境数据分叉。

## 10. 验收标准

迁移完成后，建议按以下标准验收：

- 新 HA 入口访问正常。
- 应用核心业务流程验证通过。
- 数据库 HA 状态正常，数据完整。
- MinIO 分布式集群状态正常，核心文件访问正常。
- DNS 已切换到新环境。
- 旧环境进入只读或待命观察状态。
- 迁移日志、备份文件、校验记录完整留存。
- 客户确认业务可用并完成验收签字或邮件确认。

## 11. 客户配合事项

客户侧需要提前配合确认：

- 正式迁移窗口和业务停写时间。
- 旧环境服务器、数据库、MinIO、DNS 和证书访问权限。
- 新环境服务器资源和网络策略。
- DNS 管理权限或切换联系人。
- 业务验证人员和验收标准。
- 回滚决策人和紧急联系方式。
