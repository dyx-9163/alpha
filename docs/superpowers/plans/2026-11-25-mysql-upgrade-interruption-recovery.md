# MySQL 离线升级中断恢复修复计划

适用分支为 `codex/customer-panel-7d200842`。从 `f45884bb` 修复两项隔离环境复现的问题。验收使用模拟远端和临时 SQLite。实际升级继续由用户在 Panel 手动发起。

1. 先复现 Router 切换后、验证登记前中断。续跑读取原断点和 Router 实机版本，未登记为新版的 Router 若路由失败，沿用已校验原冷备的恢复路径。覆盖之前已经验证登记的 Router，保留其版本和冷备引用。覆盖恢复旧目录后、启动前收到 TERM 的情况。
2. Panel 重启恢复时标识真正中断的 MySQL 升级任务，保留其原锁。续跑核对相同的断点、集群和节点，用有时限的远端互斥检查确认原脚本已退出。校验成功后一次事务接管该集群升级所需锁。覆盖远端仍忙、正常失败、没有断点、锁已被他人持有及并发重复续跑。Panel 在恢复任务之前取得 SQLite 对应的进程锁，防止第二个实例把正在运行的任务标记为已中断。
3. 执行 Bash 语法、升级及 HTTP API、Store、Worker 回归测试。对比已知的全量测试基线，构建 Linux 和 Windows 后端，执行 Windows 隔离冒烟，提交并推送客户分支。
