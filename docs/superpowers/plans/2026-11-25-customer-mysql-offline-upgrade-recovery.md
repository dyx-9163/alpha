# MySQL 客户分支离线升级修复计划

目标是在 `codex/customer-panel-7d200842` 上补齐 MySQL 8.0.36 到 8.4.13 的故障恢复和续跑。保留原八步升级入口。测试使用模拟远端和临时 SQLite。

1. 远端失败恢复
   - 冷备失败时等待旧进程就绪并记录恢复结果。
   - MySQL 首次尝试启动 8.4 前恢复失败切换的目录和配置。首次尝试后保留数据和冷备，按实机状态判断恢复路径。
   - Router 切换失败时恢复原进程。每台通过读写和已配置只读路由验证后再处理下一台。
2. 节点切换与超时
   - 完成冷备校验后，在停止 MySQL 前再次核对主节点 UUID 和三个 ONLINE 成员。
   - 上传、检查和远端阶段设置截止时间。远端优先接收 TERM 并执行恢复，同一节点的升级脚本持互斥锁。
3. 失败后安全续跑与并发
   - 完成冷备后保存原任务、离线包指纹、节点身份及基线。逐台登记已经复验的版本。
   - 从原入口手动续跑时校验原冷备、原节点及实际工具和服务版本。复用原任务工作路径，跳过已完成节点。最终一次事务更新版本并结束断点。
   - 升级持有目标服务器配置锁。探测只提交仍适用于该服务器配置的状态。
4. 验证与交付
   - 覆盖归档失败、目录恢复、Router 路由失败、节点状态变化、断点续跑、发送超时和配置互斥。
   - 检查脚本语法、后端测试、前端测试和构建。提交并推送客户分支。现场升级从 Panel 手动发起。
