# MinIO 双节点迁到 Silo 的修复计划

适用于客户分支 MinIO 2025-10-15 双节点双向桶复制迁到 Silo 20261112。保留 Panel 手动发起入口、两端停服后分别冷备、两份归档校验后再切二进制的顺序。实现和验收使用本地隔离环境。

1. 修复停服、冷备和失败恢复
   - 两端分别记录实际停服、归档、切换、启动与回退状态。停服前校验失败时，只恢复已证实被任务变更且安全恢复的站点。
   - 冷备和切换前后复核嵌套挂载。阶段设置截止时间，两端独立执行恢复，连接失败时保留证据。
   - 任何站点已尝试启动 Silo 或状态不明时，保留成对冷备。仅停止确认是 Silo 的服务，禁止以旧 MinIO 打开可能被新版写过的存储。
2. 修复中断续跑和 Panel 并发
   - 停服前持久化原任务、双节点身份、原工作路径及复制基线。续跑先复核两端状态，并复用原冷备。遇到原版本回退已开始的情况，完成旧服务恢复后结束原断点。
   - 复用服务器配置锁和 SQLite 接管事务。Panel 重启后只接管同组、同断点且已确认没有远端阶段运行的锁。
   - 巡检只合并观测字段。两端验收后原子写版本、产品和备份引用，同时关闭断点。巡检对照实际运行的产品和版本。
3. 补复制验收
   - 对比两端真实桶清单、管理范围、版本化及复制规则。现有复制链路通过专用、唯一测试键验证双向到达与字节校验，精确清理测试版本。
   - 不能安全执行测试的规则或存储配置要在切换前报告。测试失败时保留冷备和断点。
4. 验证与发布
   - 检查迁移脚本语法，运行 MinIO、HTTP API、Store、Worker 专项和全量基线对照，构建客户版并用隔离环境验证。必要验证通过后提交并推送客户分支。
