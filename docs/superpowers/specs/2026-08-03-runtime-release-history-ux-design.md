# AIFAR Runtime 发布历史关键交互优化设计

日期：2026-08-03
状态：用户已授权直接实施前三项优化

## 1. 目标与范围

本轮只处理发布历史审计中的三项高优先级问题：

1. 直接显示一条发布当前生效的服务范围，不再只显示含义模糊的“当前”标签。
2. 提交回滚前展示真实受影响服务、这些服务的当前 revision 和目标 release，仍要求填写回滚原因并保留“业务数据不会自动回滚”的警告。
3. 将删除动作明确命名为“删除发布记录”，并让回滚、删除的禁用原因无需悬浮即可读取。

本轮不增加发布详情抽屉、操作人/任务入口、分页筛选、时区改造或实时刷新逻辑。

## 2. 现状与约束

- 后端已经按服务返回 `currentServices` 和 `rollbackServices`，回滚与删除资格由后端判定。
- 当前发布可能是部分服务当前，因此一个实例可以同时有多条带当前服务的发布记录。
- 删除只移除面板发布记录和关联索引，不删除远端制品、容器或运行状态。
- 回滚继续使用现有 worker、任务、审计和双重校验，不改变远端执行与数据语义。
- 所有新增文案必须提供中文和英文；页面样式沿用现有 Element Plus 和运行时设计 token。

## 3. 方案比较

### 方案 A：表格显式展示范围，确认框展示影响（采用）

增加“当前生效”列，显示 `当前 X/Y` 和当前服务名称；操作区直接显示禁用原因。回滚弹窗列出实际 `rollbackServices` 以及 `当前 revision → 目标 release`。

优点是无需猜测或悬浮，部分生效和实际回滚范围都清楚；代价是表格增加一列、行高略有增加。

### 方案 B：保留当前布局，只强化 Tooltip

改动最小，但键盘用户和触摸设备仍难获得关键信息，也不能解决两条记录都显示“当前”的歧义，因此不采用。

### 方案 C：新增发布详情抽屉

信息最完整，但超出本轮前三项范围，且关键安全信息仍不应隐藏在二次操作中，因此留作后续迭代。

## 4. API 与数据设计

发布列表项新增只读字段：

```text
currentServiceRevisions: Record<string, string>
```

该映射只包含 `rollbackServices` 中服务的当前 revision。后端从实例 metadata 的 `serviceRevisions` 读取，缺少服务级值时按现有全局 `currentRevision`、`releaseId` 顺序回退。空值不写入映射。

此字段仅用于回滚影响预览，不参与资格判断。既有 `currentServices`、`rollbackServices`、`rollbackAvailable` 和删除资格字段仍是权威合同。

## 5. 前端交互设计

### 5.1 当前生效范围

- 发布 ID 列只保留 ID，避免将部分服务状态混入 ID。
- 新增“当前生效”列。
- 若 `currentServices` 非空，显示信息 Tag：`当前 {current}/{total}`，下方显示当前服务名称。
- `total` 使用 `changedServices`、`currentServices`、`rollbackServices` 的有序去重并集，兼容旧记录字段不完整的情况。
- 若没有当前服务，显示 `—`。
- Tag 提供包含完整服务名称的 `title` 和 `aria-label`，但可见文字本身已能表达计数与名称。

### 5.2 回滚影响预览

- 继续使用现有带 textarea 的 MessageBox，避免新增独立对话框状态。
- 消息区域使用安全的 Vue VNode，不拼接 HTML。
- 依次展示目标发布、受影响服务数量、服务清单、每个服务的 `当前 revision → 目标 release`，最后显示业务数据不自动回滚警告。
- 输入框仍必填回滚原因；请求只提交后端返回的 `rollbackServices`。
- 当前 revision 缺失时显示统一的“未知”，不阻止后端已有资格与锁内复验。

### 5.3 删除与禁用原因

- 表格按钮、确认框标题和确认按钮统一使用“删除发布记录”/`Delete release record`。
- 回滚或删除不可用时，在操作按钮下方显示对应原因；Tooltip 继续保留为补充说明。
- 两个动作都不可用时分别显示原因，避免将不同安全边界合并成含糊提示。
- 可见原因使用次要文字色和 12px 字号，不使用错误色制造误报警。

## 6. 错误处理与安全边界

- 前端展示不替代后端回滚和删除校验。
- 列表刷新后若资格变化，提交时仍由后端拒绝过期请求。
- 不读取或展示制品内容、凭据、连接串或敏感 metadata。
- 不执行真实 Runtime 回滚或删除作为自动化测试。

## 7. 测试与验收

遵循 TDD，每项行为先增加失败测试并确认失败原因：

1. 后端列表响应只为可回滚服务返回当前 revision 映射，并覆盖服务级值、全局回退和空值。
2. 当前范围组件显示 `当前 X/Y` 和可见服务名称，非当前记录显示 `—`。
3. 删除按钮和确认按钮使用“删除发布记录”。
4. 禁用原因直接出现在表格内容中，不只存在于 Tooltip。
5. 回滚确认消息包含目标 release、实际受影响服务和 revision 变化，提交 payload 仍只包含 `rollbackServices`。
6. 运行受影响前后端测试、完整前端测试、后端测试和前端生产构建，最后执行 `git diff --check`。

## 8. 不变项

- 不新增数据库迁移。
- 不修改发布保留数量和远端制品清理规则。
- 不改变回滚脚本、任务类型、API 路径或审计动作。
- 不提交或推送本轮代码，除非用户另行要求。
