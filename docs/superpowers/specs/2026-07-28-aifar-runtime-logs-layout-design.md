# AIFAR Runtime 日志页布局优化设计

日期：2026-07-28
状态：已确认，待实施

## 1. 背景

当前“容器 > AIFAR 运行时 > 日志”页面同时纵向堆叠运行时工具栏、实例详情、一级资源标签、诊断包记录、实时日志筛选器和日志工作区。在 1920×1080 截图中，诊断包表格占据了主要可用高度，实时日志仅剩很小的可视区域；顶部操作按钮和实例信息也存在重复与密度过高的问题。

本次优化只调整前端信息结构和视觉层级，不改变 Runtime 状态采集、实时日志 SSE、诊断包导出、下载、删除、任务跟踪或后端 API。

## 2. 目标

1. 让“查看实时日志”成为日志页默认且占据主要空间的任务。
2. 将“管理诊断归档”作为同级但独立的任务，避免与实时日志纵向争抢高度。
3. 降低运行时顶部操作区和实例信息区的视觉密度。
4. 保留全部现有功能、权限、禁用原因、任务状态和实时刷新行为。
5. 在 1920×1080 和 1440×900 桌面窗口中保持清晰，在窄屏下可自然换行且不遮挡操作。

## 3. 已选方向

采用“方案 A：双层标签聚焦”。

在现有 Runtime 一级资源标签的“日志”面板内增加二级标签：

- `实时日志`：默认选中，展示实时日志筛选器、流控制、状态摘要和日志工作区。
- `诊断归档（数量）`：展示诊断包列表和“导出诊断包”入口。

两个任务互斥展示，不再同时纵向堆叠。

未采用的方向：

- 归档摘要条：上下文连续，但展开归档表格后仍会挤压实时日志。
- 宽屏侧栏：超宽屏利用率较好，但在 1440px 和更窄窗口中会造成横向拥挤，响应式复杂度更高。

## 4. 页面结构

### 4.1 Runtime 顶部工具栏

顶部工具栏保持单行优先，分为状态区和操作区。

状态区包含：

- Runtime 总体状态；
- Agent 状态；
- 当前 Runtime 实例选择器。

高频或高影响操作直接展示：

- 运行参数；
- 批量更新；
- 全部重启（读取新配置）。

低频操作收入“更多操作”下拉菜单：

- 安装服务；
- 同步运行时；
- 清理残留。

刷新使用独立图标按钮，并保留加载态与可访问名称。所有原有禁用原因继续通过 tooltip 或菜单项说明展示，危险操作原有确认流程不变。

当可用宽度不足时，操作区整体换到下一行；不把按钮文字进一步压缩为难以理解的缩写。

### 4.2 实例摘要

当前三行 KeyValueGrid 改为紧凑单行摘要，默认展示：

- 实例标识与 Runtime 模式；
- 安装目录；
- 运行参数版本状态；
- 应用状态；
- Agent 状态。

长实例标识和路径使用省略显示，并通过 tooltip 提供完整值。窄屏时摘要项自动换行。若现有 KeyValueGrid 无法满足紧凑布局，则新增 Runtime 专用摘要组件，不改变通用 KeyValueGrid 的其他页面表现。

### 4.3 日志二级标签

在 `AifarRuntimeLogsTab.vue` 内增加日志工作区二级标签，不增加新路由：

- `live`：实时日志；
- `archives`：诊断归档。

默认值为 `live`。在当前页面生命周期内切换 Runtime 一级标签后再返回“日志”，保留最近选择的二级标签；切换服务器或 Runtime 实例时重置为 `live`，避免把上一个实例的归档上下文带到新实例。

二级标签使用 Element Plus 的可键盘操作标签组件或等价语义组件。选中态同时使用文字、下划线/背景和 `aria-selected` 表达，不只依赖颜色。

### 4.4 实时日志面板

实时日志面板移除诊断包列表后，结构为：

1. 筛选与流控制工具栏；
2. 告警提示；
3. 未选择范围/未开始接收状态；
4. Pod 范围条；
5. 流状态与统计；
6. 占据剩余高度的日志虚拟列表。

筛选器位于左侧，流控制位于右侧；1440px 宽度不足时允许两组换行。保持现有服务、Pod、级别、关键字、尾部行数、仅看错误、开始/重新接收、暂停/恢复、清空和自动滚动功能。

实时日志 SSE 生命周期保持不变。切换到“诊断归档”时不主动清空已接收日志；是否关闭流继续遵循现有组件卸载和页面可见性逻辑，本次不引入新的后台流策略。

### 4.5 诊断归档面板

`AifarRuntimeDiagnosticsPanel.vue` 只在 `archives` 二级标签中渲染，占据完整日志内容区。

标题区展示：

- 标题“诊断归档”；
- 说明“日志来源：宿主机挂载日志”；
- 记录数量；
- 主操作“导出诊断包”。

表格从当前八列收敛为六列：

1. 状态：状态标签与警告数量合并；警告详情仍通过 tooltip 查看。
2. 时间范围：开始时间和结束时间分两行展示。
3. 服务：显示前若干服务及总数，完整列表通过 tooltip 查看。
4. 归档：存储位置和文件大小合并展示。
5. 生命周期：创建时间和过期时间分两行展示。
6. 操作：详情、下载、删除保持原权限和禁用逻辑。

表格占用可用剩余高度，不再固定为 280px。历史远端归档、已删除、生成中、失败、取消、过期等待清理等状态继续完整呈现。

导出弹窗、估算信息、大小限制、服务器时区、存储配额和提交前置条件不变。

## 5. 组件与状态边界

预期修改范围：

- `web/src/containers/runtime/AifarRuntimeWorkspace.vue`
  - 重组顶部状态、实例选择和操作分组；
  - 使用紧凑实例摘要。
- `web/src/containers/runtime/AifarRuntimeLogsTab.vue`
  - 增加 `live/archives` 二级标签和切换状态；
  - 分离两个任务区域。
- `web/src/containers/runtime/AifarRuntimeDiagnosticsPanel.vue`
  - 合并表格字段并适配全高内容区；
  - 展示记录总数。
- `web/src/containers/runtime/runtime.css`
  - 新增紧凑工具栏、摘要、二级标签和响应式样式。
- `web/src/i18n/messages.ts`
  - 新增或调整中英文用户可见文案。

不修改：

- 后端 API 与数据库；
- `aifar-agent`；
- SSE 协议；
- 诊断包导出、下载和删除业务逻辑；
- Runtime 一级资源标签路由。

二级标签状态应放在 Runtime 前端上下文或日志组件本地状态中。只有多个组件需要读写时才提升到共享 context，避免为单一视觉状态扩大公共接口。

## 6. 状态与异常处理

- 无 Runtime 实例：沿用当前空状态，不展示日志二级标签。
- 无诊断包：归档标签仍可进入并显示空状态与导出按钮。
- 诊断任务进行中：归档标签数量和列表通过现有任务进度机制刷新，不新增轮询。
- Runtime 降级或操作被禁用：保留现有禁用原因，不因收进菜单而丢失说明。
- 窄屏：顶部操作换行，实例摘要按项换行，归档表格允许水平滚动；操作列保持可见。
- 长文本：实例路径、服务列表和错误信息使用省略与 tooltip，不能截断后无查看方式。

## 7. 可访问性

- 二级标签必须支持 Tab 键聚焦和方向键/Enter 激活，遵循所用组件的标准键盘行为。
- 图标刷新按钮提供明确的可访问名称和 tooltip。
- 状态必须同时提供文字，不以绿、橙、红颜色作为唯一信息。
- 下拉菜单项保留禁用状态和原因说明。
- 交互目标保持现有 Element Plus 按钮尺寸，不为追求紧凑缩小到难以点击。
- 视觉验收之外，还需检查 DOM 阅读顺序、焦点可见性和 200% 缩放下的重排。

## 8. 测试与验收

### 8.1 逻辑与组件测试

- 默认进入日志页时选择“实时日志”。
- 二级标签可在实时日志与诊断归档之间切换。
- 切换服务器或 Runtime 实例后重置为实时日志。
- 诊断归档数量、状态、警告、存储和生命周期合并展示正确。
- “更多操作”中的每项继续调用原有动作，并保留禁用与加载状态。
- 诊断导出、下载、删除和任务完成刷新测试继续通过。

### 8.2 构建与回归

- 运行 `pnpm test:web`。
- 运行 `pnpm web:build`。
- 不执行离线打包。

### 8.3 视觉验收

在真实页面数据状态下检查：

- 1920×1080：实时日志虚拟列表获得页面主要高度，顶部操作不拥挤。
- 1440×900：顶部和筛选工具栏合理换行，不出现按钮遮挡或正文横向溢出。
- 诊断归档：六列表格可读，操作列稳定，长服务列表和提示可查看。
- 中文与英文：按钮、标签和表头不溢出。
- 参考截图与实现截图使用相同视口并排比较，修正可见的间距、裁切、边框和层级问题。

## 9. 完成标准

满足以下条件才可视为完成：

1. 日志页默认只展示实时日志工作区，诊断归档不再挤压其高度。
2. 诊断归档可通过二级标签完整访问，所有现有动作可用。
3. 顶部工具栏和实例信息区明显降低密度，但不存在功能丢失。
4. 关键桌面视口、中文和英文视觉验收通过。
5. 前端测试和构建通过，未修改后端与 `aifar-agent`，未执行离线打包。
