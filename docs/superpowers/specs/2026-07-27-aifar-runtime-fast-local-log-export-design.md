# AIFAR Runtime 宿主机日志快速导出设计

日期：2026-07-27

状态：已完成需求确认，待用户审阅

## 1. 背景与目标

现有 Runtime 诊断导出方案包含 Docker 容器运行时日志，并将最终归档保存在目标服务器。这不符合当前需求：业务日志已经挂载到目标服务器磁盘，大日志若先在目标服务器生成完整归档，再由浏览器或面板间接下载，会增加磁盘占用、等待时间与失败恢复成本。

本设计将日志导出调整为：仅从目标服务器的宿主机挂载日志目录读取日志，在目标服务器完成单次扫描、时间过滤和脱敏，通过 SSH 将压缩流直接传输到 `aifar-server`，最终文件由 `aifar-server` 本地保存、下载、删除和过期清理。

目标如下：

- 只导出宿主机挂载日志，不读取 Docker stdout/stderr。
- 按每条日志记录的时间，以目标服务器时区精确过滤。
- 无法识别时间戳的内容默认跳过，并把警告写入归档。
- 避免在目标服务器生成最终大归档；只允许受控的临时过滤文件。
- 最终归档存储在 `aifar-server`，支持配额、保留期、下载和删除。
- 采用一个明确的“快速档”，以硬限制控制耗时和磁盘风险。
- 不要求升级或修改 `aifar-agent`。

本文档取代 `2026-07-27-aifar-runtime-diagnostic-export-design.md` 中关于日志来源、归档存储、容量限制、保留期、下载和删除的设计。原方案中的非日志运行态诊断项继续保留，除非本文明确修改。

## 2. 范围与非目标

### 2.1 本期范围

- `agent-runtime-v2` 实例的 Runtime 诊断估算与导出。
- 目标服务器宿主机挂载日志的发现、精确时间过滤、脱敏和归档。
- 非日志诊断数据的继续采集。
- SSH 压缩流到 `aifar-server` 的本地归档落盘。
- 本地归档元数据、下载、手动删除、自动过期和配额控制。
- 任务步骤、SSE 进度、审计、取消与失败清理。
- 对既有远端归档记录的有限兼容。

### 2.2 非目标

- 不调用 `docker logs`，不读取 Docker JSON 日志驱动文件，也不生成 `container-logs/`。
- 不增加 Docker 日志开关或高级导出模式。
- 不修改 `aifar-agent`，不要求 agent 在线。
- 不提供自由 shell、任意文件路径或任意目录下载 API。
- 不建设集中式日志检索平台，也不替代 Loki、Elasticsearch 等日志系统。
- 不提供大于快速档限制的后台慢速导出；超限时要求拆分服务或缩小时间范围。
- 本轮设计评审后才编写实施计划；本文档本身不包含业务代码改动。

## 3. 用户流程

1. 用户在 Runtime 诊断页面选择单个实例、服务和时间范围。
2. 前端调用估算接口，页面明确显示日志来源为“宿主机挂载日志”。
3. 估算结果展示候选扫描量、硬限制、预计耗时范围、`aifar-server` 可用空间/配额和归档过期时间。
4. 预检通过后，用户创建导出任务。
5. 页面通过任务 SSE 展示过滤、压缩传输、校验和清理进度，并可跳转任务中心。
6. 任务成功后，导出记录进入 `ready`，用户可下载或手动删除。
7. 归档到期后自动删除；下载默认不会删除归档。

默认 `deleteAfterDownload=false`。若调用方显式启用，服务端仅在完整响应发送成功后删除本地归档。

## 4. 总体架构

### 4.1 数据流

```text
宿主机挂载日志
    -> 安全发现与快照边界
    -> 单次扫描：解析时间、过滤、脱敏
    -> 目标服务器受控临时过滤目录
    -> manifest / README / warnings / 非日志诊断
    -> tar.gz 写 stdout
    -> SSH 流式传输
    -> aifar-server 的 .partial 文件
    -> 大小与 SHA256 校验、fsync
    -> 原子重命名为最终归档
    -> 本地下载 / 删除 / 过期清理
```

目标服务器不保存最终归档。受控临时目录在成功、失败和取消时都必须清理。`aifar-server` 同步计算接收字节数和 SHA256，只有校验、同步与原子重命名完成后，导出记录才能进入 `ready`。

### 4.2 组件职责

`httpapi`：

- 解析和验证请求。
- 创建任务、写审计并返回 task id。
- 提供估算、列表、下载和删除端点。
- 不直接包含远程采集脚本或业务采集逻辑。

诊断导出 service：

- 验证实例类型、时间范围、服务选择和权限。
- 执行容量预检和本地配额预留。
- 编排远程过滤、流式归档、本地落盘、状态迁移和清理。
- 保持稳定错误码和可审计状态。

SSH adapter：

- 在现有远程命令执行基础上增加受控命令 stdout 流读取能力。
- 支持 context 取消、远程进程组终止、有限 stderr、接收端写错误传播和字节计数。
- 该能力只供内部构造的固定命令使用，不暴露自由 shell API。

本地归档 repository：

- 在配置根目录下安全创建 `.partial` 和最终归档。
- 负责目录/文件权限、相对路径校验、配额、保留期、原子提交、下载打开和删除。
- 启动时协调数据库记录与本地文件，清理陈旧 `.partial` 和孤儿文件。

## 5. 日志来源与安全发现

### 5.1 唯一日志来源

日志根目录固定为：

```text
<installRoot>/runtime/logs/<service>/
```

该路径对应 Runtime 将宿主机目录挂载到容器 `/opt/aifar/logs` 的持久化日志。服务选择只能映射到平台已知服务名，不能由请求直接拼接任意路径。

### 5.2 可接受文件

允许常见活动与滚动日志，例如：

- `*.log`
- `*.log.N`
- `*.log.YYYY-MM-DD.N`

发现阶段必须：

- 使用受控根目录和相对路径。
- 拒绝符号链接、隐藏文件、目录穿越和根目录外路径。
- 拒绝 `.idx`、配置文件、数据库文件、密钥、凭据及其他敏感文件类型。
- 记录每个活动文件在任务开始时已打开 inode 的初始大小。
- 仅扫描该初始大小范围；任务开始后追加的内容留到下一次导出。
- 文件被替换或 inode 异常变化时安全失败或跳过并记录结构化警告，不追随新目标。

文件和目录检查必须尽量使用文件描述符约束，避免检查后到读取前被符号链接替换的 TOCTOU 风险。

## 6. 时间过滤语义

### 6.1 时间区间与时区

过滤区间统一为：

```text
[since, until)
```

即 `since` 包含，`until` 不包含。任务开始时读取并固定目标服务器时区，写入 `manifest.json`：

- 日志时间自带 `Z` 或 UTC offset 时，按其明确时区解释。
- 日志时间不带 offset 时，按任务开始时捕获的目标服务器时区解释。
- 不使用浏览器时区或 `aifar-server` 时区替代目标服务器时区。

### 6.2 支持的时间戳

首版支持：

- Spring/Java：`YYYY-MM-DD HH:mm:ss[.,fraction]`
- ISO 8601：带 `Z` 或 UTC offset
- JSON 字段：`timestamp`、`time`、`@timestamp`、`ts`
- Nginx access：`[dd/Mon/YYYY:HH:mm:ss ±HHMM]`
- Nginx error：`YYYY/MM/DD HH:mm:ss`

解析器按明确优先级选择格式，并在 manifest 中记录每个文件实际使用的 parser 格式。

### 6.3 日志记录块

过滤单位是“日志记录块”，不是孤立文本行。带可识别时间戳的行开始一条新记录；下列典型续行附属于当前记录：

- `Caused by:`
- `Suppressed:`
- Java 栈帧 `at ...`
- `... N more`
- 明确缩进且符合续行规则的内容

记录首行时间在 `[since, until)` 内时，整个记录块进入输出；否则整个记录块跳过。

### 6.4 无法识别的内容

采用 fail-closed 行为：

- 普通无时间戳行无法可靠归属时跳过。
- 文件内完全无法识别时间格式时跳过相关内容。
- 没有前序记录的孤立续行跳过。
- 每类跳过生成结构化 warning，写入 `manifest.json` 和 `collection-errors.txt`。
- 任务日志和审计只记录警告码、服务和计数，不记录被跳过的原文、敏感路径或凭据。

无法识别时间戳不使整个任务失败。若所有日志都无匹配记录，仍生成可下载的成功归档，其中包含 README、manifest、warnings 和已采集的非日志诊断。

## 7. 远程临时过滤与压缩流

### 7.1 受控临时目录

临时目录位于：

```text
<installRoot>/runtime/diagnostics/<exportId>.partial/
```

`exportId` 由服务端生成并严格校验。目录只保存已经过时间过滤和脱敏的临时文件、manifest、说明和非日志诊断；不得复制完整原始日志，也不得生成最终归档文件。

### 7.2 一次扫描

每个候选文件只进行一次内容扫描，同时完成：

- 初始大小边界读取。
- 时间戳解析和记录块过滤。
- 敏感信息脱敏。
- 原始扫描字节、输出字节、记录数和 warning 统计。
- 过滤结果写入临时文件。

估算阶段不得为得到精确输出大小再完整扫描一遍文件。

### 7.3 流式归档

过滤结束后，目标服务器从临时目录执行固定参数的 `tar -czf -`，将归档写到 stdout。`aifar-server` 通过 SSH 直接接收该流，不在目标服务器落最终 `.tar.gz`。

流传输必须支持背压；本地写入失败、超限、取消或超时时应立即关闭流并终止远程进程组。

## 8. 非日志诊断内容

继续收集以下非日志诊断：

- 容器列表、镜像和健康状态。
- deployments。
- pods。
- agent 状态。
- 主机 CPU、内存、磁盘等资源摘要。
- release 摘要。

这些内容通过现有 SSH 能力收集，不依赖 `aifar-agent` 在线。实例必须是 `agent-runtime-v2`，但本功能不要求升级 `aifar-agent`。

## 9. 归档结构与清单

```text
aifar-diagnostics-<instance>-<timestamp>/
  README.txt
  manifest.json
  collection-errors.txt
  services/<service>/<relative-log-path>
  diagnostics/runtime-summary.json
  diagnostics/deployments.json
  diagnostics/pods.json
  diagnostics/containers.txt
  diagnostics/health-checks.txt
  diagnostics/agent-status.txt
  diagnostics/host-resources.txt
  diagnostics/release-summary.json
```

明确不包含 `container-logs/`。

`manifest.json` 至少记录：

- 导出格式版本和实现版本。
- 实例、服务器和所选服务的非敏感标识。
- `[since, until)` 时间语义。
- 目标服务器时区及其采集时间。
- 各项硬限制及实际统计。
- 每个源日志的相对路径、初始快照字节、扫描字节、过滤后字节、SHA256、parser 格式和 warning 码。
- 非日志诊断项的成功、跳过或失败状态。
- 脱敏规则版本、归档生成时间和归档内容摘要。最终 `.tar.gz` 的大小与 SHA256 记录在数据库导出记录和下载响应元数据中，避免归档自引用。

`collection-errors.txt` 使用适合人工阅读的警告摘要，不包含原始敏感日志内容和绝对路径。

## 10. 快速档限制

首版只有一个快速档：

| 限制项 | 硬限制 |
| --- | ---: |
| 单个源日志文件扫描量 | 1 GiB |
| 所有候选源日志总扫描量 | 2 GiB |
| 过滤并脱敏后的未压缩内容 | 500 MiB |
| 最终 tar.gz | 256 MiB |
| 单次任务总时长 | 15 分钟 |
| 用户选择的时间窗口 | 24 小时 |

任一限制被超过时，任务中止远程流，删除目标服务器临时目录和 `aifar-server` 本地 `.partial`，并返回稳定错误码。用户提示应明确建议按服务拆分或缩小时间范围，不得静默截断并冒充完整导出。

最终压缩大小只能在实际导出时精确校验。到达 256 MiB 时接收端停止写入并取消远程命令。

## 11. 快速估算

估算接口只做元数据级、保守估算：

- 发现允许的候选日志并读取文件元数据。
- 计算候选扫描字节，并校验单文件 1 GiB、总计 2 GiB 限制。
- 检查 `aifar-server` 当前可用磁盘、全局配额和并发预留。
- 基于候选扫描量和保守吞吐率给出预计耗时范围。
- 返回 500 MiB 过滤内容上限、256 MiB 最终归档上限和 15 分钟总超时。

估算超时保持 30 秒。估算不得完整读取日志内容，因此输出大小和耗时都标记为范围而非保证。此前目标机实测中，约 13.6 MiB 未压缩数据的旧完整流程约 10 秒，该数据只用于保守校准，不作为 UI 的精确承诺。

若元数据估算已超限、容量不足或配额无法预留，创建按钮不可用，并展示可操作的缩小范围建议。创建导出后仍以运行时硬限制为最终裁决。

## 12. aifar-server 本地存储

### 12.1 配置默认值

```text
AIFAR_DIAGNOSTIC_EXPORT_DIR=data/diagnostic-exports
AIFAR_DIAGNOSTIC_EXPORT_RETENTION_HOURS=24
AIFAR_DIAGNOSTIC_EXPORT_QUOTA_BYTES=5368709120
```

目录权限为 `0700`，归档和 `.partial` 文件权限为 `0600`。配置目录可以是绝对路径；数据库中只保存由服务端生成并验证的根目录内相对路径，不接受客户端提交的绝对路径。

### 12.2 原子落盘

接收流程：

1. 在配置根目录创建唯一 `.partial` 文件。
2. 流式写入，同时计算字节数和 SHA256。
3. 执行最终大小、归档可读性和预期元数据校验。
4. `fsync` 文件，并按平台能力同步目录元数据。
5. 原子重命名为最终文件。
6. 在数据库事务中将记录更新为 `ready`。

若第 6 步失败，应立即删除已提交的最终文件；删除失败则记录受控 cleanup 状态，交由启动协调器处理，不能留下无记录的长期孤儿文件。

### 12.3 配额与并发预留

- 全局默认配额为 5 GiB。
- 创建任务前先清理过期文件和陈旧 `.partial`。
- 每个运行中的导出按最终归档上限 256 MiB 预留空间。
- 配额判断包含 ready 文件、有效 partial 和并发预留。
- 任务终态时释放预留。
- 清理后仍不足时拒绝新导出，不静默删除未过期归档。

除逻辑配额外，还必须检查文件系统实际可用空间，并保留安全余量。

### 12.4 保留与协调

- 默认保留 24 小时。
- 自动清理只删除已过期归档和陈旧 `.partial`。
- 手动删除通过 API 执行并写审计。
- 启动时协调数据库记录与本地文件：清理陈旧 partial、处理缺失文件、校验根目录内孤儿文件。
- ready 记录对应文件缺失或摘要不匹配时，不再提供下载，并安全迁移到失败或过期状态。
- 所有删除必须再次验证相对路径仍位于配置根目录且不是符号链接。

## 13. 数据模型与兼容

在集中 `Store.migrate()` 中前向增加归档位置字段，例如：

- `storage_kind`：`local` 或 `remote`
- `storage_relative_path`：受控根目录内相对路径
- 本地归档 `size_bytes`、`sha256`、`warning_count`、`expires_at`
- 必要的 cleanup 状态和并发预留记录

状态保持：

```text
pending -> building -> ready
                    -> failed
                    -> cancelled
ready   -> expired
ready   -> deleted
```

新导出一律使用 `storage_kind=local`。已有远端归档记录继续支持下载、删除直到自然过期，避免升级后立即破坏既有记录；系统不再创建新的远端归档。兼容逻辑移除应作为后续独立迁移，不在本期静默完成。

## 14. API 契约

保留既有端点：

```text
POST   /api/v2/containers/aifar/runtime/diagnostics/estimate
POST   /api/v2/containers/aifar/runtime/diagnostics/exports
GET    /api/v2/containers/aifar/runtime/diagnostics/exports
GET    /api/v2/containers/aifar/runtime/diagnostics/exports/{id}/download
DELETE /api/v2/containers/aifar/runtime/diagnostics/exports/{id}
```

要求：

- 错误结构保持 `{ code, message, details }`。
- 创建和删除等状态变更进入 worker 并写审计。
- 创建接口返回 task id 和 export id。
- 下载端点从 `aifar-server` 本地安全打开文件；兼容期内可按 `storage_kind` 读取旧远端记录。
- 删除端点删除本地文件并更新状态；文件已不存在时幂等收敛。
- 权限、目标锁和同实例互斥规则沿用现有实现。
- 不新增接收自由 shell 或绝对日志路径的接口。

估算响应至少包含：

- `logSource=host-mounted`
- 候选文件数与候选扫描字节
- 单文件、总扫描、过滤内容、最终归档和总耗时限制
- 预计耗时范围
- 本地可用空间、已用配额、并发预留和过期时间
- 是否允许创建及稳定阻断原因

## 15. 任务、SSE 与审计

导出任务使用以下稳定步骤机器码：

1. `validate-local-storage`：检查本地空间、配额和预留。
2. `discover-log-files`：发现安全日志文件并固定快照边界。
3. `filter-and-redact`：按时间过滤并脱敏。
4. `build-manifest`：生成 manifest、README、warnings 和诊断内容。
5. `stream-local-archive`：压缩并流式传输到 `aifar-server`。
6. `verify-local-archive`：验证大小、SHA256、归档并原子提交。
7. `cleanup-remote`：清理目标服务器临时目录。

步骤、目标状态和普通日志沿用现有 worker。前端通过 SSE 获取进度，不增加浏览器轮询。用户可见任务日志、错误和审计文案进入中英文 i18n。

审计记录实例、服务器、服务选择、时间范围、结果大小、warning 数量、storage kind 和终态，不记录 SSH 密码、token、原始日志、敏感绝对路径或完整远程命令。

## 16. 取消、失败与恢复

### 16.1 取消

- worker context 取消后立即停止本地写入。
- 关闭 SSH stdout，终止远程命令进程组。
- 使用独立、短超时 cleanup context 清理远程临时目录。
- 删除本地 `.partial` 并释放配额预留。
- 状态进入 `cancelled`，清理失败进入可重试 cleanup 状态并记录脱敏警告。

### 16.2 失败分类

可降级为 warning：

- 某些行或记录无法识别时间戳。
- 某个可选非日志诊断命令失败。
- 某个日志文件在安全规则下被跳过。

必须使任务失败：

- 超过任何快速档硬限制。
- SSH 流中断、本地写入或 fsync 失败。
- SHA256、最终大小或归档结构校验失败。
- 受控根路径验证、原子提交或关键清理安全检查失败。
- 目标服务器时区无法可靠确定。

稳定错误码应区分扫描超限、过滤输出超限、归档超限、本地配额不足、本地磁盘不足、超时、流失败和安全路径失败，便于前端给出准确建议。

### 16.3 启动恢复

服务启动时：

- 删除超过安全期限且无活动任务的 `.partial`。
- 将不存在本地文件的 `ready` 记录标记为不可下载状态。
- 对根目录内无数据库记录的文件执行严格命名和年龄检查后清理或隔离。
- 释放无活动任务对应的遗留配额预留。
- 不触碰配置根目录以外的文件。

## 17. 安全设计

- 远程脚本由服务端内嵌，参数为固定结构并逐项校验。
- 服务名、export id、时间值和路径不得直接拼接为不受控 shell 文本。
- 远程临时目录和本地存储目录都执行根路径约束、符号链接拒绝和 TOCTOU 防护。
- 临时过滤文件在写入前和归档前均进行敏感文件名与路径检查。
- 日志内容应用已有或版本化的脱敏规则；归档完成前执行必要的 secret pattern 检查。
- stderr 有大小上限，返回客户端和写入任务日志前统一脱敏。
- 凭据只在既有加密存储与短生命周期 SSH 会话中使用，不写入归档、任务日志或审计。
- 下载使用受控文件句柄，不通过用户输入路径直接打开文件。
- HTTP Content-Disposition 文件名由服务端生成并清理。

## 18. 前端设计

Runtime 诊断面板保持单选实例流程，并做以下调整：

- 明示“日志来源：宿主机挂载日志”。
- 不出现 Docker 容器运行时日志选项。
- 展示 1 GiB 单文件、2 GiB 总扫描、500 MiB 过滤内容、256 MiB 归档和 15 分钟限制。
- 估算区展示候选扫描量、预计耗时范围、本地配额/磁盘、过期时间和阻断原因。
- 预检未通过时禁用创建按钮。
- 创建后通过 SSE 展示七个任务步骤，并提供任务中心链接。
- 导出记录展示“本地存储”、大小、warning 数、创建时间、过期时间和状态。
- 下载、手动删除交互保持一致；下载默认不删除。

实施前必须按仓库约定重新阅读 `design/ant-design-system-portable202606.md`，所有新增用户可见文案提供中英文。

## 20. 真实环境验收

代码实现和自动化测试完成后，再对已授权的目标服务器执行一次受控验收：

- 使用临时会话凭据，不把凭据写入代码、文档、日志或 memory。
- 验证日志只来自 `<installRoot>/runtime/logs`，归档无 `container-logs/`。
- 用跨边界样例验证 `[since, until)` 和服务器时区。
- 验证无法识别时间戳内容被跳过，warnings 正确生成。
- 验证最终归档只存在于 `aifar-server` 配置目录。
- 验证成功、取消和故障后目标服务器无测试临时目录，本地无遗留 `.partial`。
- 验证大小、SHA256、下载、手动删除和 24 小时过期逻辑。

真实验收不替代自动化 fake SSH 测试，也不在未授权时修改目标环境。

## 21. 验收标准

满足以下条件视为本功能完成：

- 新导出不读取或估算 Docker 运行时日志。
- 宿主机日志按记录时间和服务器时区精确过滤，时间区间为 `[since, until)`。
- 无法识别时间戳的内容不进入导出，并在归档中留下无敏感信息的 warning。
- 目标服务器不保留最终归档，只保留任务期间的受控临时过滤文件。
- 最终归档安全存储在 `aifar-server`，支持原子提交、配额、保留期、下载、删除和启动恢复。
- 快速档所有硬限制均在远程和接收端得到强制执行，超限不产生伪完整归档。
- 取消、失败后远程临时目录、本地 partial 和配额预留均能清理或进入可恢复 cleanup 状态。
- 不需要修改或升级 `aifar-agent`。
- 旧远端归档记录在兼容期内仍可处理，新记录全部采用本地存储。
- 后端、前端、脚本和构建验证通过，且不执行离线打包。
